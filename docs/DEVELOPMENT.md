# 开发和验证

## 文件结构

构建脚本按 `src/modules.json` 拼接源码，在同一个严格模式闭包中运行，不向网页暴露密钥或内部服务。这样安装仍只需一个 `.user.js`，源码可按模块维护。

| 模块 | 职责 |
| --- | --- |
| core.js | 公共输入校验、请求、标题规范化和缓存驱逐 |
| panel.js | 共用面板、任务互斥、JSON 停止、日志和主题 |
| manifest.js | 清单记录、百度/123 协议、选中项、请求观察、清单导入导出 |
| guangya.js | 光鸭目录与元数据、替换预览、核验和旧版清理 |
| media.js | 影视名称、季集、TMDB/AI、目录规划和写入 |
| works.js | 共用作品详情、地区译名、持久资料库和确认身份 |
| media-panel.js | 影视整理界面及执行流程 |
| subtitles.js | 字幕来源、匹配、编码、选择、下载与核验上传 |
| subtitles-panel.js | 字幕列表、选择、日志和批量任务 |
| bootstrap.js | 平台入口；页面加载前安装请求观察 |

## 命令

```sh
npm run build   # 从 src 生成唯一安装文件
npm run check   # 检查安装文件与源码完全一致及 JS 语法
npm test        # 构建一致性和所有回归测试
```

无生产依赖，也无测试依赖。测试不发起真实网盘请求。新增公共行为时应同时覆盖正常、失败和取消路径；不要以扩大自动重试掩盖写操作状态不明。

## 验证范围

测试覆盖：

- 各平台入口、fetch/Request/Headers/XHR 登录捕获、刷新 Token、可信接口域名和当前目录。
- 百度/123 直接粘贴 JSON 导入，各自的接口与目的地；光鸭省略成功码和处理中轮询；创建请求不自动重发；JSON 停止。
- 清单合法性、路径冲突、分页重复/缺失、目录创建和版本替换停止。
- 影视类型与季集、目录计划、附件保护、执行前重新核对。
- 字幕真实资源名、作品/年份/季集、防错片、双语优先、UTF-8/UTF-16/GB18030、错误网页拒绝。
- 136 个视频文件名配合模拟整季资源的复用、缺集重新搜索、缓存隔离。
- 限流冷却、取消、过期下载地址刷新、字幕候选失败后的来源补查、网盘授权中断。
- 上传状态不明的记录与对账、同名内容校验、避免重复上传。
- 已有字幕与新下载共用正文/时长检查，上传对账恢复后也需正文检查；核验缓存随视频身份、时长参考和核验策略变化失效。
- 缺少可用外置字幕时，MKV 使用受限分段请求检查容器字幕轨；发现任意字幕轨即跳过搜源与补齐，不判断语言或音画同步。无法确认的 MKV 暂停自动补齐；非 MKV 不读取视频，仍可检查和补齐外置字幕。
- 强制重读、有限对白 AI 证据判断、证据不足与错片状态、两次解析失败停用本批正文 AI；结果不代表音画同步。
- 有界并发的实际任务重叠、失败/停止后不再派发、等待活跃任务结束、同季顺序缓存，以及并发调用下 AI 解析熔断的排队执行。
- SubDL 参数、分页/缓存、严格身份筛选、单文件/ZIP 提取、CRC 与解压大小、来源暂缓/补查、无效 Key 暂停和下载不携带凭证。

记录中的作品/资源名样例只用于匹配回归；资源 ID、接口响应、网络延迟等由测试模拟。字幕正文使用合成样例。测试通过不等于已经在浏览器和真实账号完成上传，也不能保证外部服务永不返回限流、493 或未收录。

SubDL 的 API 字段参考 Bazarr 的 [SubDL provider](https://github.com/morpheus65535/bazarr/blob/master/custom_libs/subliminal_patch/providers/subdl.py) 与语言映射，实现不发送 Bazarr 专用客户端标记。实际无 Key 请求返回 `not_authorized`，仅确认 API 可达；授权搜索、真实字幕下载、收录和耗时未验证。回归使用模拟 API 和合成字幕、真实 ZIP 压缩/解压，不将其视为真实链路成功。

全功能检查结论与本次优化范围见 [2026-11-17 检查记录](REVIEW-2026-11-17.md)。

## 发布

先执行 `npm run build` 和 `npm test`，再提交源码、成品和测试。`@version`、`core.js` 中的 VERSION 与 `package.json` 必须一致；构建脚本会检查。

脚本名和 namespace 保持 v3 草稿的标识以便更新。旧 v2 脚本属于另一个标识，用户升级时需要停用它；脚本配置也属于各自的 Tampermonkey 存储。

## 3.2.0 作品与整季资源

影视整理选择作品时与字幕补充资料时共用 works.js。作品库以类型和 TMDB 编号索引；无编号时仅采用名称、年份、类型均吻合的唯一记录。库中不保存密钥或字幕签名链接，最多 1000 部、30 天有效，兼容旧版文件识别记录。原文件关联仍按完整指纹核验。

查找阶段先解析整组身份，再 prepareSeason；迅雷与 Assrt 查询季名，SubDL 使用 season_number/full_season 而不带 episode_number。各来源的原始列表对后续集重新筛选；缓存未覆盖的集才进入原单集流程。SubDL ZIP 缓存仅驻留内存（最多 3 包，每包 16 MiB），索引后逐集解压并校验 CRC；数字集名要求可信包身份和唯一季数，API 独立文件 metadata 与文件集数冲突时拒绝。

SubDL 季包、解包文件及 full_season 参数已核对 [官方 API 文档](https://subdl.com/api-doc)。本次仍未用真实账号验证授权查询或上传。

新增 shared-work-library.test.cjs 和 subtitle-season-plan.test.cjs，测试使用生产函数和合成 ZIP；涵盖实际整理选择/保存后跨上下文恢复、首集缺失、只补查缺集、单次下载、数字集名、错误季/花絮、凭证隔离和停止后等待活跃请求结束。
