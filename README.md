# 云盘媒体整理工具

当前版本 **3.2.9**。支持百度、123、光鸭网盘的 JSON 清单导入导出，以及 123、光鸭的影视整理和字幕补齐。

[安装或更新脚本](https://raw.githubusercontent.com/Yanshov/cloud-media-organizer/main/cloud-media-organizer-v3.user.js) · [变更说明](CHANGELOG.md) · [开发与验证](docs/DEVELOPMENT.md)

左下角“设置”中的“窗口与外观”可选择 960×600、1280×800（默认）、1440×900、1600×1000，立即生效并记住选择。尺寸按截图中的窗口外框像素计算（不含阴影），补偿系统显示缩放与浏览器缩放，不随屏幕分辨率放大；可用空间不足时才缩小防越界，悬停尺寸选框可查看实际外框大小。已有尺寸偏好继续保留。

页面以 1280×800 为标准排布：左侧固定功能导航，右侧集中展示当前工作，目录、进度和日志入口放在底部状态栏。窗口尺寸与外观移入设置，版本显示在导航底部。JSON 编辑区自动填满剩余高度，空白时显示使用引导，下载和复制放在编辑区上方。960×600 保留紧凑布局，窄屏改用横向导航。影视与字幕列表每页 4 项，点击展开详情；分页只影响展示，批量任务仍处理全部符合条件的项目。日志、辅助操作和说明默认收起，常规概览尽量不滚动；长详情、设置和小窗口仍可滚动。

深浅主题均使用黑白灰，通过明暗和字重区分主要操作与选中项。影视整理、字幕和 JSON 使用一致的标题与文字层级，操作按钮采用相同的中性样式；提高说明文字对比度。设置各项默认展开，仍可手动收起。界面说明与功能预览以文字描述为准；仓库不再保存界面截图。

## 安装

1. 在浏览器安装 Tampermonkey，打开上面的脚本链接并安装。
2. 只启用一份本工具。旧版“百度 / 123 / 光鸭 跨盘 JSON”使用不同脚本标识，升级后应停用旧版，避免重复拦截请求。
3. 刷新网盘网页，打开右下角工具按钮。光鸭和 123 若尚未捕获登录状态，切换一次文件夹。

为直接更新已有 v3 草稿，脚本保留原来的 `@name` 和 `@namespace`；以 `@version 3.2.9` 和工具面板版本为准。密钥在浏览器脚本设置中填写，不写入源码或仓库。

| 勾选文件/文件夹并递归导出 JSON | 支持 | 支持 | 支持 |

**跨盘清单不是文件内容。** 秒传仅在目标网盘命中相应哈希时成立；未命中会报告未完成。百度超过 256 KB 的文件需要清单没有提供的分片哈希，因此不会伪报导入成功。脚本读取网盘已有的 MD5/GCID/CID，不下载整个视频来计算这些值。

## 使用

### 跨盘清单

在网页勾选范围，点击“导出 JSON”；在目标网盘打开目标文件夹，粘贴清单后点击“导入 JSON”，或选择清单文件。目标目录会固定为本次任务开始时的位置。

同名文件不会直接覆盖。光鸭“导入新版，成功后删除对应旧版”会先展示预览，核验新版后再清理相应旧版。任务进行时可以点击“停止当前任务”；正在进行的请求结束后，后续请求停止。已提交但未确认的操作应先刷新目录核对。

### 影视整理

在 123 或光鸭勾选视频或文件夹，填写 TMDB API Key/Read Access Token，识别作品并核对电影、剧集、季集和目标路径，然后预览、执行。可选 AI 识别会发送文件名和所在目录名给配置的服务，默认不开启。字幕与关联附件随视频整理；清理功能会单独展示范围。

### 字幕补齐

1. 迅雷按片名搜索，免 Key；Assrt 需填写 Token，OpenSubtitles 按需配置。SubDL 为可选 API 来源，默认关闭，在“字幕来源与设置”填写个人 API Key 后启用，配额以服务返回为准。启用射手时先尝试视频四段指纹匹配，需要网盘允许分段读取；名称搜索依次尝试迅雷、SubDL（启用时）、Assrt、OpenSubtitles，有可靠候选时暂缓后续来源，下载失败再补查。
2. 勾选视频或文件夹，读取并检查已有字幕，再查找。
3. 优先选择简中双语、繁中双语，其次简体中文、繁体中文；显示来源的真实文件名。
4. “只看待选择”只显示需要手动选择的项目。作品或季集不能确认时不会自动上传。
5. 点击补齐，检查字幕格式、所选语言正文及已有时长参考，再上传并核验内容一致。待核验项目先点“重新检查目录”，不要重复上传。

“已有/已补齐”表示基础检查通过，不能证明字幕属于这部作品，也不能证明音画同步。担心以前传错时，点击“强制复查已有字幕”：跳过本地核验缓存、重新读取正文；若已启用影视 AI，则发送开头、中间、末尾合计最多 6000 字符的对白辅助判断。明显过短或 AI 有原文证据指向其他作品的字幕会标为待核验，暂停自动补齐，由用户核对原字幕。AI 证据不足会明确显示“作品归属未确认”。此操作不会搜索新字幕、上传、覆盖或删除文件。

检查以每个视频找到一份可用的已关联外置字幕为止，不是逐份审计该视频的所有语言版本；不读取视频音轨、不验证时间轴同步。时长检查仅使用网盘或识别记录已有的时长，不为此新增元数据请求。核验缓存绑定字幕 ID、大小、MD5、视频身份和时长参考；强制复查始终绕过缓存。

影视整理与字幕共用作品资料：保存中文名、原名、英文名、地区译名、编号和年份，兼容旧版识别记录。资料最多保存 1000 部、有效期 30 天；同名同年不唯一时不自动关联。迅雷最多使用 3 个名称并发查询（全局最多 2 个请求，发起间隔至少 1.1 秒）；Assrt 也可用日文原名补查。搜索片名不附加发行年份；年份仍用于结果核对。剧集先按季查询迅雷、Assrt 与已配置的 SubDL，复用文件列表，逐集检查，只有缺集再搜索。Assrt 限流等待可停止；已有冷却不会逐个消耗候选。网盘授权失败会中断并提示重新登录、检查目录。

目录检查最多同时处理 3 个视频，搜索最多同时处理 2 组作品；同一季逐集处理以复用整季缓存，各来源继续独立限速。上传补齐仍顺序执行。停止或授权中断后不再派发新工作，等待已发出的任务结束再解锁界面。日志记录并发策略，检查结果逐项显示。

SubDL 优先下载 API 提供的单文件，只有 ZIP 时先下载并索引包目录，再按需提取通过作品、年份、季集和语言检查的字幕。同一包在当前缓存中只下载一次，覆盖所选集数后停止下载其他包；最多缓存 3 个 ZIP，刷新或淘汰后需要重新下载。只有包的作品和季数已确认时，才允许使用 01.srt 这种数字文件名；冲突、花絮及未确认候选仍不会自动上传。之后继续执行正文及上传核验。压缩包和解压正文均限 16 MB，不支持 RAR、加密、ZIP64 和多卷；浏览器还需支持原生 deflate 解压。没有接入依赖网页会话或验证码的 SubHD。SubDL 尚无有效 Key 下的真实搜索、下载验证，不能据此保证收录或命中率。

## 源码与备份

- `cloud-media-organizer-v3.user.js`：可直接安装的完整脚本。
- `src/`：10 个源码模块及构建顺序，修改这里。
- `scripts/`：构建和测试入口，不依赖第三方 npm 包。
- `tests/`：模拟 API/DOM 和可重现的测试样例，不包含登录凭证或第三方字幕正文。

```sh
npm run build
npm test
```

Node.js 20 或以上即可。GitHub Actions 在每次提交时执行检查；下载仓库 ZIP 或 `git clone` 可恢复源码、成品和测试。

本版将 v3 草稿未迁移的功能接回，并恢复此前已验证的字幕修复。没有宣称固定成功率、内存占用或加速比例。本地测试不代表已在你的真实网盘执行过上传，接口可用性、登录状态和字幕库收录仍以实际日志为准。
