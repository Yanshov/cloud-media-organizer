## 其他功能检查与保留理由

- **跨盘 JSON（core、manifest、panel）**：清单字段、路径冲突、分页一致性、任务停止和目的地固定均有业务作用；百度、123、光鸭协议不同，不合并成通用写入/重试框架。
- **光鸭导入及替换（guangya）**：已有共享目录解析和导入循环；新版内容核验、替换日志、旧版删除及删除结果确认各自必要。导入前的新鲜目录检查用于防冲突，不替换成长缓存。
- **影视识别和整理（media、media-panel）**：已有 TMDB 请求缓存、唯一可靠结果提前停止、失败后 AI 兜底及季集中英文别名；本次只优化重复查找，保留作品身份、预览、执行前检查和每次成功后的识别记录保存。
- **字幕来源（subtitles、subtitles-panel）**：已有来源暂缓/补查、限流批次状态和 Assrt 下载熔断。本次未叠加新的请求重试，也未放宽年份、续集、季集、TMDB 编号核验。
- **入口及共用面板（bootstrap、panel）**：一次安装请求观察、任务互斥和设置归位职责不同，未发现需要删除的重复入口。没有仅凭函数长或引用少就删除业务代码。
- **构建**：九个模块仍拼接成同一闭包，只需安装完整 `.user.js`。构建一致性、语法和版本检查保留，不加入依赖。

## 实际边界与后续观察

已有字幕检查在每部视频找到一份可用字幕后停止，不逐份检查所有语言版本。强制复查不会修改网盘文件，也不负责自动替换疑似错片。AI 对白判断是建议；要求引用确实存在，仍不能证明其推理正确，更不能验证音画同步。若需验证同步，必须另有视频/音频比对能力，本次没有实现。

时长仅取已有的网盘字段或识别记录，50% 下限用于发现明显过短的字幕，不证明完整性；缺少时长时不会拒绝字幕。缓存只保留结果，不保存完整对白；账号标识沿用上传凭据的摘要方式。强制复查会重新读取字幕，启用 AI 后会增加对应调用。

全量列表重绘、日志文本回填和大量核验记录持久化仍可能有开销；没有真实耗时证据前，不增加新的调度、缓存层或批量持久化机制。下一轮实际日志应优先观察待核验原因、无时长参考占比和 AI 证据不足占比，再决定是否调整流程。

## 后续结构清理与目录读取优化

本轮基于 `b08a838`，只处理两个已确认的重复点：

- **影视预览**：删除隐藏的 `previewMedia` 按钮，以及任务锁、失效处理对它的引用。识别结束和编辑后直接调用同一个预览函数。目标冲突检查、字幕随视频规划、取消、显式确认执行仍保留；预览不会执行网盘写入。回归覆盖重新命名、待确认行、冲突、取消和目录读取失败，确认旧计划不会残留为可执行状态。
- **光鸭普通 JSON 导入**：只保留最近一次读取目录的名称索引，连续检查其中已有的文件时复用；不保留多目录缓存，也不持久化。索引找不到名称、切换目录、处理目录项目、任意提交结果或异常之后重新读取。首次读取已经确认缺失的文件不重复读第二遍；写入前不使用缓存的“缺失”结论。重复名称、同名大小/MD5 冲突、缺少元数据时跳过、停止及授权错误的处理保留。

导入日志新增一行目录读取/已有项复用计数，统计的是完整目录读取调用次数；单次读取内部仍可能有多页 HTTP 请求。模拟同目录连续 50 个已有文件，目录读取从 50 次降为 1 次，提交次数为 0。全新文件仍逐次读取目录再提交，不能据此声称全新导入也有同样加速。

复用反映的是该段只读处理开始时的已有文件快照；运行中若在别处修改或删除了已有文件，需要下一次导入重新读取才能发现。没有扩大为长期缓存，也没有删掉写入前检查。

未引入通用来源、轮询、任务、存储或错误处理框架。未完成上传凭据是防重复提交的恢复记录，不按条数驱逐；只沿用原先明确成功或明确失败后的清理规则。

本轮新增预览生命周期和目录复用回归，原断言保留。验证为构建产物上的模拟 API/DOM 测试，未在真实账号下测量请求节省或执行上传、改名、删除。

## 剧集字幕查找的重复等待

检查基线 `131b245`。代码路径中，每集即使已有确认过的 Assrt 整季文件列表，仍先取得视频下载地址、串行读取四段各 4KB，再请求射手，之后才使用整季缓存。每段读取和射手查询各有 8 秒超时。这是已确认的重复等待路径，没有本次真实运行日志，不能断言它是用户全部耗时的唯一原因。

改为先复查迅雷、Assrt 的内存缓存。迅雷沿用有界搜索缓存保存原响应，只有其中确实包含当前准确集数才有机会复用；Assrt 沿用整季文件列表缓存。均按当前视频重新检查作品、年份、准确季集、语言和版本冲突，能自动选中时才跳过该集取样与来源搜索。缓存按作品、年份、TMDB 编号和季隔离，Assrt 还按 Token 隔离。缺集、片名或季集不明、合并多集以及无法可靠选择的情况继续原流程。缓存不继承上一集的 AI 结论或未经当前行确认的别名，不新增持久化记录或网络重试。

下载失败后仍可补查暂缓的其他来源，不重复下载同一批已失败的缓存候选。下载正文、语言、时长、上传、核验和对账保持原流程。新增“来源耗时”（查询与候选判断分别计时，后者含 AI）、“别名耗时”和“单片耗时”，缓存成功明确记录“整季快速命中”。

新增回归使用真实构建产物与模拟来源响应：11 集整季场景中，Assrt 全季包或包含其他集数的迅雷响应均只需第一集的一次哈希匹配，后续十集无新增取样或来源 HTTP 请求。覆盖错误身份、缺集、未知季集、账号隔离、取消、退出清缓存及失败后补查；不据此宣称迅雷实际每次都会返回整季。未测量真实账号速度，未在真实浏览器和网盘账号执行上传、改名、删除。
